# Rust rewrite — decisions (owner-approved)

- 2026-11-21 Code lives on branch `rust`; `main` (auto-deploys to prod via CI) is untouched until a single cutover.
- 2026-11-21 Parity 1:1, Telegram bot is the top priority: every screen, section, button, text and callback must match `telegram-bot-spec.md`.
- 2026-11-21 Telegram Stories (MTProto, mtcute) stay in TypeScript as a small sidecar; Rust calls it.
- 2026-11-21 Tests: port only the key ones (delivery invariants, callback/parity contracts, public site contract, DB/migration guards), not all 1,146.
- 2026-11-21 All Rust build output / temp files go to `_trash-rust/` (git-excluded, `rm -rf _trash-rust` to clean).
- 2026-11-21 Bot interface is Russian only: no `en` interface locale, no 🌐 Language settings screen (spec §4.10.6), only `ru` catalog strings are ported; menu fingerprint/locale-dependent bits use `ru` constantly. English CONTENT stays: English posts, `en` targets/channels, `schedule_en`, the `en` queue filter are unchanged. Code, comments and logs remain English (repo rule).
- 2026-11-21 Russian-only consequence: `setMyCommands` description uses the `ru` string (today it is EN). `ru.json` is exported with the EN value wherever the `ru` key is missing, because `t()` falls back to `catalog.en` — that keeps today's rendered output.
- 2026-11-21 Deliberate deviation from 1:1: `conversationSessions.save` carries the expected-revision check in the upsert's own `WHERE` (`ON CONFLICT … DO UPDATE … WHERE revision = expected`; zero rows → `action.session-stale`) instead of reading the revision first, as the delivery invariants require. Non-racing results are identical to TypeScript; a revision bumped between read and write is refused instead of overwritten.
- 2026-11-21 Russian-only consequence: an actor with no stored locale reads as `en` in TS (spec §1.4/§8 says `ru`); Rust always renders `ru`. Goldens are recorded with `ru` stored explicitly. `entry/bootstrap.json` (setMyCommands, EN in TS) differs from Rust on purpose.
- 2026-11-21 Deliberate deviation from 1:1: `retryVideoTarget` carries the retryable status it read in the target update's own `WHERE` (`… AND status = ?`; zero rows → `err.retry-only-failed`, nothing armed) instead of writing unconditionally, as the delivery invariants require. Non-racing results are identical to TypeScript; a target that moved between read and write is refused instead of overwritten.
- 2026-11-21 Deliberate deviation from 1:1: `refreshXToken` writes the renewed pair only if the `platform_tokens` row is still the one it read (`UPDATE … WHERE updated_at = ? AND sealed_refresh_token IS ?`; with no row read, `INSERT … ON CONFLICT DO NOTHING`) instead of upserting unconditionally, as the delivery invariants require. Zero rows → `XRefresh::Superseded`: neither the row nor the live config is touched and the loop logs it at info. The OAuth callback still writes unconditionally. Non-racing results are identical to TypeScript; a pair reconnected between read and write is kept instead of overwritten by the older refresh.
- 2026-11-21 `crates/foundation/locales/ru.json` is the source of truth for the interface catalog: exported once from `catalog.ts`, edited by hand since; `scripts/rust/export-ru-catalog.ts` refuses to overwrite it. First edit: `settings.category-system-body` drops «язык» (no language setting) — «⚙️ Система\n\nЧасы, копия базы и цифры, которые вводятся руками.»; the golden harness asserts the recorded TS text and expects the new one (`deliberate_deviations`).
- 2026-11-21 Story cards: an emoji inside the headline renders in colour (Noto Color Emoji via resvg), not as the text-coloured silhouette librsvg drew. Layout and line breaks are unchanged; the pixel fixtures cover cards without an inline emoji.
- 2026-11-21 Deliberate deviations (delivery invariants) in `crates/adapters`: any Stories sidecar answer other than an explicit "not sent" settles as ambiguous; a YouTube upload or Reels publish that succeeded without returning an id is reported with no id instead of failing into a retry (second post); result-object key order may differ from TS where requests stay byte-identical.
- 2026-11-21 Deliberate deviations (delivery invariants) in `crates/delivery` and `crates/adapters`: a split Discord post refused on a later message returns a partial publication (`_discordMessageIds`) and the retry sends only the rest (TS threw and re-posted the first message); reconciliation confirms a job and its target together, the target fenced on still being the unanswered publication, and releases the job when it moved; a video publish job whose target is held for verification completes without touching the target (TS failed it into a retryable state, i.e. a second upload); a publish attempt is dropped at its timeout instead of running on unobserved.
- 2026-11-22 Cutover: the live TypeScript comparisons became committed goldens recorded under ffmpeg 6.1.1 (the CI and production build). Delivery scenarios keep their `DATA_DIR` under `/tmp/solo-publisher-goldens/` on every machine, because media cache keys hash the file's path; the channels golden writes the runtime row's build revision as `<revision>`. Tests that could only compare against a running TypeScript (`typescript_adopts_a_rust_database`, the TS half of the secret-box round trip) are dropped; the secret box now round-trips in Rust and still opens the TypeScript-sealed fixtures.
- 2026-11-22 Deliberate deviation from 1:1: `story-media-prune` and `disk` list Story variants sorted by name, not in the filesystem's directory order (which differed between hosts and broke the ops golden on CI); the golden's plan is in sorted order.
- 2026-11-22 The image keeps `bun /app/entrypoint/config-check.js`, which the deploy agent runs on a new image before replacing the container; it runs `studio-entrypoint --check-config` (configuration loaded, nothing else). The agent and its rollback path stay unchanged.
- 2026-11-22 Delivery scenario media inputs are committed bytes (`crates/delivery/tests/fixtures/`), not made by ffmpeg at test time: the mpeg4 clip came out different per core count (slice threading), and the site golden hashes what is derived from it. What ffmpeg's encoders write (WebP variants, posters) is compared by path and links, with names taken from their hashes read as the file they name, because those bytes follow the ffmpeg build.
- 2026-11-24 Telegram Stories run in process on grammers 0.12 (`crates/mtproto`, `mtproto::MtprotoStories` behind `adapters::StoriesClient`), superseding the 2026-11-21 sidecar: `sidecars/stories`, its HTTP contract, `STORIES_SIDECAR_URL`/`_TOKEN` and the entrypoint's supervision are gone; `studio-entrypoint` execs the Studio; `ops telegram-stories-login` signs in itself.
- 2026-11-24 The Stories session file stays in mtcute 0.32's SQLite layout (`auth_keys`, `key_value['dc_main']` as `serializeBasicDcOption`), read and written by `mtproto::session::SessionFile`, so production's signed-in account carries over without a new sign-in. A new home DC or permanent key is written back (`dc_main` as version 2); grammers' peers and update state stay in memory; a test-server session is refused.
- 2026-11-24 Deliberate deviation (delivery invariants): a Story that fails before `stories.sendStory` is handed to the sender — connect, identity, channel resolution, the upload, or the 120 s deadline running out during them — is not sent; TypeScript counted any non-RPC error inside mtcute's `sendStory` (an upload deadline included) as possibly posted. After it, an RPC error with code 500 and up or negative is ambiguous (TypeScript: every RPC error was not sent). Nothing is retried except a flood wait of at most 10 s; a dropped connection never is.
- 2026-11-24 `stories.sendStory` is byte-identical to mtcute's (`crates/mtproto/tests/send_story.golden.json`, recorded from the sidecar's `sendStoryParams` before deletion) except where the upload differs: the file is named by its base name, where mtcute sent the absolute path it was given (`InputFile.name`, `documentAttributeFilename`); the upload carries its MD5 (mtcute: empty) in 512 KiB parts.
- 2026-11-24 `foundation::time` looks zones up in the bundled tzdb explicitly: grammers enables jiff's default features, which would otherwise put the host's `/usr/share/zoneinfo` first and accept names `Intl` refused (`posixrules`).
- 2026-11-24 The remote media processor is Rust (`crates/media_processor`, binary `media-processor`, hyper 1 on a current-thread runtime), superseding `deploy/media-processor/*.ts`: routes, auth, status codes, bodies, JSON shapes and key order, the cache layout, the hourly 24 h prune, port 8787 and every `MEDIA_PROCESSOR_*` variable are unchanged; `site_vertical` is kept although no client sends it. Its image is `debian:trixie-slim` with Debian's `ffmpeg` and `intel-media-va-driver` — the distribution the `oven/bun:1.4.0-debian` base was built on — and no Bun.
- 2026-11-24 One vertical media recipe (`crates/vertical_media`) for both executors, `Encoder::{Software, Vaapi}` being the only thing the argv branches on (device args, `format=nv12,hwupload`, codec flags). The VAAPI argv is byte-identical to the TypeScript (`crates/vertical_media/tests/remote_recipe.golden.json`, recorded from `story-encode.ts` before its deletion); the local software argv is unchanged. The probes stay apart: remotely duration is capped at 59 s and absent audio counts as 128 kbps, locally neither.
- 2026-11-24 Deliberate deviations in the media processor: a `MEDIA_PROCESSOR_*` number that does not parse refuses the start (TypeScript ran with `NaN`); the work and cache directories are created at start; a request sharing a render that threw gets 503 `media_processing_shared_job_failed` (TypeScript: 500); a filesystem or spawn failure is a 500 with a `media_processor_error: …` text body, and an unmeasurable work disk a 500 `media_processor_work_dir_unavailable: …` (TypeScript: Bun's error page); an ffprobe that cannot start reads as an unreadable source; `/health` `queued` is always 0 (distinct work was never queued); the bearer token is compared in constant time; SIGTERM stops the process (PID 1). The completion log line keeps the TypeScript shape (`job`, `timings` at the top level), not the Studio logger's `details`.
- 2026-11-24 The media image rebuilds on `crates/media_processor`, `crates/vertical_media`, the workspace `Cargo.toml`/`Cargo.lock` and `deploy/media-processor/{compose.yml,Dockerfile*}`; `vertical_media`, `Cargo.toml` and `Cargo.lock` rebuild the Studio image too, `crates/media_processor` does not. `shared/` is gone (`serial-queue.ts` with its last caller, `theme-script.ts` had none).
- 2026-11-24 Developer and CI tooling is `cargo xtask` (`crates/xtask`, alias in `.cargo/config.toml`), superseding `scripts/{ops-prod,image-smoke,check,check-steps,check-docker-workspaces,enforce-typescript}.ts`: `check [--jobs N] [STEP...]` (language, typescript, fmt, clippy, test, build — serial, stops at the first failure; lefthook's pre-push and CI's `rust` job run it), `ops-prod`, `image-smoke <image>` (the image as an argument, not `IMAGE`). Dropped: knip and its `tools/knip` workspace, biome (lint and the pre-commit formatter), taze, the Dockerfile workspace gate (no stage installs with Bun). The language gate inverts: no TypeScript, JavaScript, Python or shell source outside the allow-list in `crates/xtask/src/check.rs`. What stays on Bun is the deploy tooling and its tests (`deploy/*.ts`, `scripts/deploy-release.ts`), run by `bun run typecheck` and `bun run test` (one script, with the coverage ratchet and the `no-network.ts` preload of `bunfig.toml`), `bun audit`, and lefthook's installer.
- 2026-11-24 Deliberate change: the production route is spelled `cargo xtask ops-prod [--as alex|maru]`. It runs `/app/bin/ops` directly as `-u 1000` (it ran `bun /app/ops/cli.js` as `-u bun`, the same uid and, by the image's passwd, the same groups), passes `OPS_INVOCATION=cargo xtask ops-prod --as <name>`, prints `ops-prod → <name> (<container>)`, and reads `OPS_SSH_TARGET` from the repository root's `.env.local` when the variable is not set (Bun loaded the file from the working directory). The guide's production prefix and `parity/ops/catalog.json` say `cargo xtask ops-prod`; the local prefix (`bun run --filter @solo-publisher/backend ops`) is unchanged.
- 2026-11-24 The deploy agent is Rust (`crates/deploy_agent`, binary `deploy-agent`, hyper 1 on a current-thread runtime), superseding `deploy/{deploy-agent,retry}.ts`: routes, bearer check, status codes, `{ok, target, release, currentRevision}` and `{ok: false, message}` bodies, the state file, env file rewriting, every `docker`/`docker compose` argv but one, the 90 s/2 s/5 s health timings, the 150 s remote timeout, the lock, the retry schedule and the notification texts and `deploy_rb_ask:`/`deploy_pr_ask:` callbacks are unchanged, and so is every `DEPLOY_*` variable. Deliberate changes: the configuration check runs `docker compose … run --rm --no-deps --entrypoint /app/bin/studio-entrypoint <service> --check-config` (it ran `--entrypoint bun <service> /app/entrypoint/config-check.js`, which only wrapped that binary); a request runs detached from its connection, so a caller hanging up no longer cancels a deployment between replacing a container and rolling it back; state and env files are written beside the target and renamed into place; every URL it calls must be `http://`, checked at start; a remote agent that refuses the connection is retried, its error being the OS's `Connection refused`, which the transient pattern matches; a request that times out is not; a non-boolean `configCheck` refuses the start. Kept as they were though inert: `docker image inspect <container name>` for the running image's digest and id, which Docker resolves only for images.
- 2026-11-24 The configuration check is a per-target setting, `"configCheck"` in `DEPLOY_TARGETS_JSON` (on unless `false`), so the Studio host's targets keep it with no env edit and the media processor's target, whose image has no `studio-entrypoint`, turns it off. A request that names no target goes to `alex`, or to the only target of an agent that drives one: the Studio host's agent calls the media processor host's agent as `POST /v1/deploy`, and the July agent there resolved that through `DEPLOY_DEFAULT_TARGET`, which stays removed. Its single-target variables are not read; `deploy/README.md` derives `DEPLOY_TARGETS_JSON` from them once.
- 2026-11-24 The agent binary is distributed in the Studio image (`/app/bin/deploy-agent`, built in the same Dockerfile stage for `$(uname -m)-unknown-linux-musl`, so it runs on the host whatever its glibc: the builder is bookworm, glibc 2.36, newer than e.g. AlmaLinux 9's 2.34). `cargo xtask deploy-release` copies it out of the image it is deploying (`docker create` + `docker cp`) into `/home/deploy/bin/deploy-agent` on every run and restarts the unit only when the bytes differ; it no longer ships or touches `deploy/deploy-agent.ts`/`retry.ts` on the host. Which agent the restart runs is the unit's `ExecStart`, switched once per host by hand. VM-106's agent is not updated by any deployment.
- 2026-11-24 `scripts/deploy-release.ts` is `cargo xtask deploy-release` (same steps, argv and order; `DEPLOY_AGENT_CHANGED` is gone). The reconciliation reads the agent's state file with `cat` and parses it in the xtask instead of `bun -e` on the host, and `IMAGE` must be a `ghcr.io/alexgetmancom/solo-publisher` digest before anything runs. `check-family-routes.ts` is `cargo xtask family-routes` (CI pipes `caddy adapt` into it); `proxy-topology.test.ts` is `crates/xtask/tests/proxy_topology.rs`. Gone with the last TypeScript: `package.json`, `bun.lock`, `bunfig.toml` (the coverage ratchet over the deployment tooling, and the `no-network.ts` preload that guarded those tests' global `fetch`), the `tsconfig`s, `.github/actions/setup-bun`, CI's `Static checks` and `Tests with coverage threshold` jobs, the `typescript` step of `cargo xtask check`, and lefthook's npm installer (lefthook is installed on its own). `bun audit` is `cargo-audit audit` on `Cargo.lock`, when it changes and weekly.
- 2026-11-24 Bun leaves the Studio image, superseding the 2026-11-22 config-check shim: the runtime base is `debian:trixie-slim@sha256:8aa5a7bf…` (the media processor's pin; `oven/bun:1.4.0-slim` was itself Debian trixie plus `ca-certificates` and Bun). On it, as before: `ca-certificates`, `tini`, setpriv from util-linux, and the static ffmpeg/ffprobe 6.1.1 from `mwader/static-ffmpeg:6.1.1@sha256:a44cd22b…`. `crates/ops/image/cli.js` and `crates/entrypoint/image/config-check.js` are deleted: both hosts run the Rust deploy agent, which runs `studio-entrypoint --check-config` itself.
- 2026-11-24 The runtime user is `studio` (was `bun`): created by the `Dockerfile` as `bun` was by its base (uid 1000, gid 1000, `/home/studio`, `/bin/sh`), so the data volumes, owned by uid 1000, carry over untouched. `studio-entrypoint` drops to it; `cargo xtask ops-prod` keeps `-u 1000`; `docker exec` takes `-u studio`.
- 2026-11-24 The healthcheck is `studio-entrypoint --ready` in both compose files (was `bun -e fetch(…/readyz)`): `GET /readyz` on `127.0.0.1:$PORT` (8788 in both files, the port the fetch named), healthy on a 2xx, 4 s timeouts under compose's 5 s. `studio-entrypoint` now refuses an unknown argument: ignoring one as root started a second Studio. Cost, for the one release whose rollback target predates this: that image's entrypoint ignores `--ready`, and the Studio it then starts exits on the taken port before any worker, so a rollback to it under the new compose file reports unhealthy while the rolled-back Studio itself runs. `deploy-release` installs `deploy/studio.compose.yaml` on every deployment; no host step.
- 2026-11-24 Deliberate change: a self-hosted Studio's operations route is `docker compose exec app ops <command>` (`/app/bin` is on the image's PATH), and `guide`'s local prefix without `OPS_INVOCATION` is `ops` (was `bun run --filter @solo-publisher/backend ops`, a TypeScript workspace that no longer exists); `parity/ops/catalog.json` and `parity/ops/scenarios/mcp.json` are edited for it.
