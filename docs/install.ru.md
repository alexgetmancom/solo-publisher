# Установка и запуск Studio

Понадобятся Docker и домен, DNS которого уже указывает на эту машину. Образ
публикуется для linux/amd64 и linux/arm64, поэтому на ARM-сервере ничего
собирать не нужно.

```bash
curl -fsSL https://raw.githubusercontent.com/alexgetmancom/solo-publisher/main/install.sh | sh -s -- publisher.example.com
```

Скрипт останавливается до того, как что-то изменит, если нет Docker или домен не
резолвится в эту машину, — это две причины, по которым установка выглядит
успешной, а система не работает. Дальше он сам пишет `.env` со сгенерированными
тремя секретами, поднимает стек, ждёт `/readyz` через Caddy и печатает адрес
Command Center вместе с токеном. Повторный запуск обновляет установку:
существующий `.env` остаётся нетронутым.

Caddy сам получает и продлевает TLS-сертификат, поэтому ни certbot, ни таймер
продления настраивать не нужно. Ссылка на Command Center, которую напечатал
установщик, входит с `COMMAND_CENTER_TOKEN` из `.env`: пустая Studio откроется
тремя шагами до первого черновика, а не пустой аналитикой.

Порты публикует только Caddy; приложение доступно исключительно через него.
Больше ничего в `.env` для запуска не требуется — Studio без credentials
площадок обслуживает Command Center и никуда не публикует. Добавьте Telegram или
MCP как интерфейс автора, затем подключайте назначения в Command Center →
Studio; `docker compose exec app bun /app/ops/cli.js doctor` покажет, чего не
хватает каждому включённому назначению. См.
[Подключение площадки](destinations.ru.md).

## Публичный сайт

Публичный сайт по умолчанию выключен — большинству нужен конвейер публикации в
уже существующие каналы, а не ещё один сайт, за которым надо следить. Включите
его через operations CLI внутри контейнера:

```bash
docker compose exec app bun /app/ops/cli.js studio-profile-set --site-enabled
```

Сайт с лентами, sitemap и Markdown-эндпоинтами появится по адресу
`https://ваш-домен/` со следующего запроса.

Временные медиафайлы, которые внешняя площадка забирает во время публикации,
складываются в `/data/media`. Контейнер сам создаёт этот каталог и исправляет
владельца до сброса root-прав. Маршрут `/media/staging/` доступен даже при
выключенном публичном сайте, поэтому для свежего self-host не нужны ручные
`mkdir` и `chmod`.

## Профиль Studio

`docker compose exec app bun /app/ops/cli.js studio-profile` показывает, от чьего
имени публикует эта Studio, её часовой пояс, наличие публичного сайта и тайминги
видео; `studio-profile-set` в той же CLI их меняет. Они лежат в базе, поэтому
переживают передеплой и не требуют рестарта.

## Видео больше 50 МБ

Telegram не отдаёт файлы больше 50 МБ, что меньше короткого видео. Чтобы
публиковать видео, укажите в `.env` `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и
`COMPOSE_PROFILES=telegram` — рядом с приложением поднимется локальный Bot API и
предел станет 2 ГБ.

## Резервные копии в первый же день

Когда настроен Telegram, Studio ежедневно и беззвучно присылает копию своей базы
в тот же чат Telegram, из которого вы пишете. Медиафайлы в неё не входят и сами
никуда не уезжают: Studio отдаёт их потоком, а забирает машина, которой владеете
вы. Пока этого не случалось неделю, `doctor` считает деплой нездоровым. Обе
половины и рецепт forced command для забирающей стороны — в
[Резервных копиях](backups.ru.md).

## Обновление

Перед обновлением `docker compose exec app bun /app/ops/cli.js status` показывает
текущий `gitRevision`. `latest` следует за revision, работающей в production
автора; чтобы оставить проверенную установку неизменной, укажите в `.env`
`SOLO_PUBLISHER_IMAGE=ghcr.io/alexgetmancom/solo-publisher:<полный-gitRevision>`.
Обновление образа — `docker compose pull && docker compose up -d`, диагностика —
`docker compose logs -f app`.

## Запуск из исходников

Понадобятся [Bun 1.3.14](https://bun.sh/) и нативные зависимости, необходимые для
сборки `sharp`. Скопируйте шаблон секретов:

```bash
cp apps/backend/secrets.env.example apps/backend/secrets.env
```

От чьего имени публикует Studio, обслуживает ли она публичный сайт, её часовой
пояс и параметры видео лежат в её собственной базе и читаются/меняются через
`bun run --filter @solo-publisher/backend ops -- studio-profile`. Ключи остаются
в игнорируемом `apps/backend/secrets.env`, а площадки — в реестре каналов.
Публикация текста, видео и сбор аналитики работают всегда.

Приватный Telegram-бот и MCP-эндпоинт работают с одними и теми же сервисами
Studio. Посты, созданные через любой интерфейс, попадают в общие черновики,
расписание, задания публикации и аналитику.

Для MCP-клиента на другом компьютере встроенный
[плагин `studio`](../plugin/README.md) объединяет удалённый транспорт и навык
управления. Его [установочный prompt](../plugin/setup-prompt.md) подключает и
проверяет deployment без доступа к базе данных или SSH.
