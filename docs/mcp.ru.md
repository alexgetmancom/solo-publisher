# Управление Studio из агента

`/api/mcp` — это весь интерфейс. Агент на вашем ноутбуке пишет, публикует,
ставит в расписание, читает аналитику и диагностирует доставку через него: без
доступа к базе, без SSH и без копии этого репозитория на той машине.

## Включить

`install.sh` генерирует обе настройки сам, так что установленная им Studio уже
отвечает здесь — возьмите их из написанного им `.env`. Если задаёте вручную:

```dotenv
# openssl rand -hex 32
MCP_STUDIO_TOKEN=
# Кому принадлежит работа агента. Ваш числовой id в Telegram, если вы пишете ещё
# и из бота, — тогда оба интерфейса владеют одними черновиками; иначе любое
# положительное целое: вне базы этой Studio оно ничего не значит.
MCP_STUDIO_ACTOR_ID=1
```

Обе задаются вместе или никак: токен, действующий ни от чьего имени, отклоняется
на старте. Отдельная запись в списке актору не нужна — его авторизует сам токен.
`STUDIO_ACTOR_IDS` существует для другого случая, когда работой здесь владеет
второй человек; установка с одним агентом оставляет его пустым.

```bash
docker compose up -d
docker compose exec app bun /app/ops/cli.js doctor
```

`doctor` покажет `studioTransportConfigured: true`, когда обе настройки на месте.

## Направить агента

Адрес — `https://ваш-домен/api/mcp`, авторизация заголовком
`Authorization: Bearer <MCP_STUDIO_TOKEN>`. Он доступен независимо от того,
обслуживает ли эта Studio публичный сайт: при `site_enabled: false` отвечают
операторские экраны и этот транспорт, и больше ничего.

Для Claude Code, Codex и всего, что говорит по MCP поверх HTTP, встроенный
[плагин `studio`](../plugin/README.md) объединяет транспорт с навыком, который им
управляет, — так одна установка даёт агенту всю Studio, а не список
необъяснённых инструментов. Его [установочный prompt](../plugin/setup-prompt.md)
подключает и проверяет связь, ни разу не печатая ваш токен.

Проверить транспорт руками, до привлечения агента:

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: Bearer $MCP_STUDIO_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  https://ваш-домен/api/mcp
```

`200` — транспорт жив. `401` — токен не совпал или не задан. `404` — что-то
перед Studio не пробрасывает путь; со стеком из этого репозитория Caddy
пробрасывает его всегда.

## Что агент может и чего не может

Открыты все читающие операции CLI: диагностика этой Студии — то, ради чего
агентная поверхность и существует. Из меняющих открыты те, что входят в обычную
работу с доставкой. То есть агент может подключать и отключать каналы, смотреть
доставку и журнал, повторять цель, править и переносить публикацию — и не может
снять бэкап, восстановить его или пройти вход в YouTube и Telegram Stories,
потому что там креды и терминал. Несколько редких изменений — объявление вехи,
починка дат, добор метрик — тоже только в CLI: их запускают раз в сезон, и
примечание с сухим прогоном должны быть перед глазами у того, кто запускает.

```bash
docker compose exec app bun /app/ops/cli.js guide --json
```

Этот каталог — тот же, что видит агент: у каждой операции указан раздел, меняет
ли она данные и доступна ли она агенту вообще. По умолчанию он отвечает индексом
симптомов и именами разделов; `--section <имя>` разворачивает один раздел
целиком, `--all` — весь каталог.
